# Workout App

筋トレの記録・目標管理・成長の可視化を目的としたWebアプリです。

自分のトレーニング内容を記録し、過去の記録を振り返ることで、トレーニングによる成長を実感できることを目的として開発しています。

個人での利用を想定していますが、ユーザー登録・ログイン機能を実装し、複数のユーザーがそれぞれ自分のトレーニングデータを管理できる構成にしています。

また、実装から始めるのではなく、

**要件定義 → 設計 → 実装 → テスト → 改善**

という開発工程を経験することを目的として開発しています。

# 要件定義

## アプリの目的

筋トレの記録を残し、過去のトレーニングや体重の変化を確認することで、自分の成長を可視化し、トレーニングのモチベーションにつなげる。

## 想定ユーザー

筋トレを継続しており、

* トレーニング内容を記録したい
* 過去の記録を確認したい
* 目標を設定したい
* 体重の変化を確認したい
* 自分の成長を確認したい

というユーザーを想定しています。

---

# 主な機能

## ユーザー機能

* ユーザー登録
* ログイン
* ログアウト
* ユーザーごとのデータ管理

ログインしているユーザー自身のデータのみを表示・編集・削除できる構成にしています。

---

## トレーニング記録

* トレーニング日の記録
* トレーニングのメモ・コメント
* 1回のトレーニングに複数の種目を登録
* 1つの種目に複数のセットを登録
* セットごとの重量・回数を記録

例えば、

ベンチプレス

1セット目：60kg × 10回
2セット目：60kg × 8回
3セット目：55kg × 8回

のように記録できます。

---

## 記録管理

* トレーニング履歴の確認
* トレーニング記録の編集
* トレーニング記録の削除
* 種目の追加
* 種目の削除
* セットの追加
* セットの編集
* セットの削除
* トレーニング履歴を日付順に表示

---

## 目標管理

* 今後の目標を設定
* 1ヶ月後の目標を設定
* 設定した目標をホーム画面に表示
* 目標の編集

---

## 体重管理

* 日付ごとの体重を記録
* 同じ日付の体重を更新
* 過去の体重を確認
* 体重履歴の表示
* 体重記録の編集
* 体重記録の削除
* 体重推移のグラフ表示

---

## トレーニングカレンダー

* 月間カレンダー表示
* トレーニングを行った日の表示
* トレーニングを行った日から記録を確認
* トレーニング履歴画面への移動
* ホーム画面への移動

---

## 統計・グラフ

トレーニングの記録をもとに、成長を確認できる統計機能を実装しています。

* トレーニング回数
* 種目数
* セット数
* 体重推移グラフ
* 種目別の重量推移グラフ
* 種目別の最高重量
* 種目を選択して重量推移を確認

グラフの表示にはChart.jsを使用しています。

# 各画面

## ログイン画面

ユーザー名とパスワードを入力してログインします。

新規ユーザーはユーザー登録画面からアカウントを作成できます。

---

## ホーム画面

ログイン後に表示されるメイン画面です。

以下の情報を確認できます。

* ログインユーザー
* 現在の目標
* 1ヶ月後の目標
* 現在の体重
* 各機能への移動

ホーム画面を起点として、各機能へ移動できる構成にしています。

---

## トレーニング記録画面

トレーニングの記録を登録できます。

Workout
   ↓
Exercise
   ↓
WorkoutSet

という構造で、1回のトレーニングに複数の種目を登録し、各種目に複数のセットを登録できます。

---

## 目標設定画面

今後の目標や1ヶ月後の目標を設定・編集できます。

設定した目標はホーム画面から確認できます。

---

## 体重記録画面

日付と体重を入力して体重を記録します。

同じ日付に複数の体重を登録した場合は、最新の記録を現在の体重として扱う設計にしています。

---

## 体重履歴画面

過去の体重記録を日付順に確認できます。

また、Chart.jsを使用して体重の推移をグラフで表示します。

---

## トレーニングカレンダー画面

月間カレンダーからトレーニングを行った日を確認できます。

トレーニングを行った日を選択することで、その日のトレーニング記録を確認できます。

---

## 統計画面

トレーニングの記録を集計し、以下を確認できます。

* トレーニング回数
* 種目数
* セット数
* 体重推移
* 種目別重量推移
* 種目別最高重量

種目を選択することで、その種目の重量推移をグラフで確認できます。

---

# データ設計

現在、以下のモデル構成で設計・実装しています。

User
│
├── Goal
│
├── Workout
│   │
│   └── Exercise
│       │
│       └── WorkoutSet
│
└── WeightRecord

## User

Django標準のUserモデルを使用しています。

ユーザー登録・ログインなどの認証を管理します。

---

## Goal

ユーザーの目標を管理します。

* 今後の目標
* 1ヶ月後の目標

---

## Workout

1回のトレーニングを管理します。

* ユーザー
* トレーニング日
* メモ
* 作成日時

WorkoutはUserに紐づいています。

---

## Exercise

トレーニング内の種目を管理します。

* トレーニング
* 種目名

1つのWorkoutに複数のExerciseを登録できます。

---

## WorkoutSet

種目ごとのセットを管理します。

* 種目
* 重量
* 回数

1つのExerciseに複数のWorkoutSetを登録できます。

---

## WeightRecord

ユーザーの体重記録を管理します。

* ユーザー
* 日付
* 体重
* 作成日時

ユーザーごとに体重データを管理しています。

---

# データベース設計

各モデルをリレーションで関連付けています。

User
 │
 ├── 1 : N ── Goal
 │
 ├── 1 : N ── Workout
 │              │
 │              └── 1 : N ── Exercise
 │                              │
 │                              └── 1 : N ── WorkoutSet
 │
 └── 1 : N ── WeightRecord

トレーニングについては、

**ユーザー → トレーニング → 種目 → セット**

という階層構造でデータを管理しています。

---

# セキュリティ・データ管理

ログインしているユーザーを基準にデータを取得することで、ユーザーごとのデータを分離しています。

例えばトレーニング記録の取得では、ログインユーザー自身のWorkoutのみを対象としています。

また、編集・削除についても、対象データがログインユーザー自身のものであることを確認する構成にしています。

未ログイン状態では、ログインが必要な画面へアクセスできないようにしています。

---

# UI・レスポンシブ対応

スマートフォンでの利用を主に想定していますが、PCから利用した場合にも見やすいようにレスポンシブデザインを採用しています。

以下を意識してUIを設計しています。

* スマートフォンでも操作しやすい
* PCでも画面を確認しやすい
* ボタンを押しやすくする
* フォームを入力しやすくする
* グラフを画面幅に合わせる
* カレンダーを見やすくする
* 各画面のデザインを統一する
* ホーム画面を起点として各機能へ移動できるようにする

# 開発・実行方法

## 1. リポジトリを取得

GitHubからリポジトリを取得します。

git clone git@github.com:UK6655-2026/workout-app.git
cd workout-app

---

## 2. 仮想環境の有効化

プロジェクトディレクトリで以下を実行します。

source .venv/bin/activate

仮想環境が有効になると、ターミナルの先頭に以下のように表示されます。

(.venv)

---

## 3. 依存パッケージのインストール

必要なパッケージをインストールします。

pip install -r requirements.txt

---

## 4. データベースのマイグレーション

python manage.py migrate

---

## 5. Django開発サーバーの起動

python manage.py runserver

ブラウザから以下にアクセスします。

http://127.0.0.1:8000/workouts/

---

## 6. 自動テスト

以下のコマンドでDjangoの自動テストを実行できます。

python manage.py test

---

# GitHubへの変更反映

ローカルで変更した場合は、以下の流れでGitHubへ反映します。

git status
git add .
git commit -m "変更内容"
git push origin main

GitHubの`main`ブランチへpushすると、RenderのAuto-Deployによって本番環境へ自動的にデプロイされます。

本番環境ではPostgreSQLを使用しています。

# 本番環境へのデプロイ

GitHubの`main`ブランチとRenderを連携しています。

GitHubへpushすると、Renderが変更を検知し、自動的にBuild・Deployを実行します。

本番環境では以下を使用しています。

* Render
* PostgreSQL
* Gunicorn
* WhiteNoise

Build時には以下の処理を実行します。

pip install -r requirements.txt
python manage.py collectstatic --no-input
python manage.py migrate

WebサービスはGunicornを使用して起動します。

gunicorn config.wsgi:application
